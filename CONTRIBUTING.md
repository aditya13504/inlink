# Contributing

1. Read `docs/requirements.md`, `docs/architecture.md`, and `docs/threat-model.md`.
2. Keep the protocol independent of Flutter UI code.
3. Add tests for state transitions and malformed inputs.
4. Do not introduce custom cryptographic primitives.
5. Do not commit credentials, private keys, signing certificates, or production data.
6. Update the relevant architecture decision record when a significant design choice changes.
7. Clearly label incomplete features; never imply unimplemented security or delivery guarantees are present.
